# Site matrix

The setup and plans of every LIME EMR site: status and key dates, patient ID and registration,
modules, forms per program, and DHIS2 reporting through OpenFn.

Everything is in one file: [`sites.yaml`](sites.yaml).

- `sites.<site>`: one entry per site. Everything above `detected` is decided by people (in the Site
  Matrix app, by hand, or by Claude from requirements). `detected` is what the repo configures
  today, generated by `scripts/site-profiles/extract.py`.
- `how_to_apply`: where each item is configured in the repo, so a person or an AI implementer can
  turn a site's decisions into config changes.
- `catalog`: the shared forms (with their program) and the key modules (with their frontend apps).

Work still to do for a site is what its decisions ask for that `detected` does not show yet:
`python3 scripts/site-profiles/gaps.py <site>` prints it as a checklist.

The Site Matrix app (`tools/site-matrix`, deployed on Vercel) reads this file live from GitHub and
saves every change as a commit by the person who signed in.

Workflow and scripts: see the `site-profiles` skill in `.claude/skills/site-profiles/SKILL.md`.
